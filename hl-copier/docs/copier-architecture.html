Как работает наш копир.

Механически он прост: читаем лида → считаем пропорцию → сводим нашу позицию → исполняем. Отличие от биржевых копиров — не в механике, а в риск-ядре: восемь фильтров в строгом порядке между «что делает лид» и «что делаем мы».

Вход: два источника, биржа — эталон

лид с Hyperliquid, наша позиция — с Binance по факту

Лид (цель)

Hyperliquid · clearinghouseState
  • Позиции, плечо, средняя входа цели
  • База пропорции = max(перп-эквити, спот-USDC) — не сумма (иначе двойной счёт)
  • TWAP-набор виден как рост чистой позиции → мы за ним следуем
  • Поток: ws (мгновенно) · опрос 30с

Мы (счёт)

Binance · positionRisk / account
  • Наша реальная позиция и эквити — всегда с биржи
  • Атрибуция бот/ручное: _bot_orders, _bot_pos
  • Сверка каждый тик: цель ↔ факт → дельта
Принцип: биржа — источник истины. Позиция берётся из positionRisk, а не из внутреннего учёта — поэтому нет «призрачных» и «зомби»-позиций, которые ведёт бот, а на бирже их нет.

Честная пропорция

CODE
contrib = размер_лида × mark × (наш_рукав / база_лида)

Копируем долю от банка лида, а не фиксированный объём/коэффициент. Если лид открыл на 2% своего капитала — у нас тоже ≈2% нашего.

база: max(перп, спот)UIproportion_include_spoton

Заморозка на старте

UI

Позиции лида, которые на момент подхвата уже в хорошем плюсе, не копируем — не запрыгиваем в уехавшую сделку. Разморозка, когда лид её закроет.

Фильтр монет

UI
whitelist ∧ (skip_builder → пропустить «xyz:»)

Whitelist ограничивает набор монет; builder-dex перпы (нефть/акции/pre-IPO) можно скипать — их на Binance нет.

4

Кэп на монету

UI
|notional[coin]| ≤ max_notional_per_coin_usd

Потолок экспозиции в одну монету — чтобы один инструмент не занял весь риск.

max_notional_per_coin_usd$50 000
5

Множитель размера

UI
notional × size_multiplier (≤0 → трактуем как ×1)

Масштабирует пропорцию лида перед кэпом плеча. ×1 — точная пропорция; 0.5 — половина; 2 — вдвое агрессивнее.

size_multiplier×1.0 (default)
6

Кэп плеча (гросс)

UIлог: «ужал x…»
if gross > equity × leverage_cap → ужать всё пропорц. · ≤0 = БЕЗ кэпа

Главный предохранитель малого счёта: ограничивает суммарную экспозицию. Лид на 467% — мы clamp'нуты до 3×. 0 = полный миррор риска лида.

leverage_cap3× гросс
7

Плечо на позицию

UI
mirror: min(плечо_лида, mirror_max_leverage) · fixed: fixed_leverage

Режим mirror берёт плечо лида (с потолком); fixed — своё фиксированное. Влияет на маржу позиции, не на её размер.

leverage_mode mirrormirror_max_leverage 100fixed_leverage 5
8

Маржинальный буфер

CODE · хардкод 10%
if req_margin > equity × (1 − buf) → ужать размер

Никогда не занимаем 100% маржи — оставляем запас под комиссию/проскальзывание, иначе биржа отклонит открытие (-2019). Единственный рычаг риск-ядра, которого нет в UI.

margin_buffer_pct0.10 (хардкод)
D

Гейты сведения — где решается «слать ордер или нет»

после плана, перед исполнением

Favorability-гейт UI

УВЕЛИЧЕНИЕ (открытие/долив): пропустить, если цена хуже входа лида > tol%
СОКРАЩЕНИЕ / ЗАКРЫТИЕ: гейт НЕ трогает — выход за лидом всегда проходит

Бережёт твою среднюю: не докупаем сильно выше средней лида. tol=1% → добор разрешён пока цена ≤ вход +1%. Это и есть причина «доливок по хорошей цене».

favorability_gate onfavorability_tol_pct1%

Auto-sync UI

Движение лида (target изменился) → применяем сразу
Догон дрейфа (лид не двигался, разошлись мы) → откладываем до кнопки «Синхронизировать»

При off бот не откупает твои ручные тримы «в плюс» — следует только за новыми движениями лида. Твой ручной оверлей уважается.

auto_syncoff

Round-up минимума UI

суб-минимальное ОТКРЫТИЕ ноги → поднять до minNotional
прочие суб-мин правки → dead-band (не дёргаем)

Иначе мелкую ногу лида не скопировать вовсе. Округление к шагу лота — тут же был фикс -1111 (float-хвост).

min_notional_roundupon

Область управления UI

off → бот ведёт всю позицию как копию
on → реконсилит только свою суб-позицию, ручное не трогает

Определяет, считать ли твои ручные сделки частью копии или отдельным «карманом».
